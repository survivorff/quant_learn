# 02 · 深度学习与序列模型

> 优先级 P1。**别急着上这一章。** 在表格因子数据上，深度学习相对梯度提升树没有稳定优势。
>
> 但有几个特定场景，深度学习确实是对的工具。这一章讲清"什么时候值得，什么时候是浪费时间"。

---

## 一、什么时候深度学习值得用

| 场景 | 为什么值得 | 数据要求 |
|---|---|---|
| **订单簿序列** | 高维、有空间结构（档位）+ 时间结构，样本量大 | L2 深度数据，海量 |
| **高频价格序列** | 样本量足够支撑大模型 | tick 级数据 |
| **非结构化数据** | 文本、图像，树模型无法直接处理 | 新闻、社媒 |
| 多任务/多标的联合建模 | 参数共享，缓解单标的样本不足 | 多标的面板 |
| 端到端优化 | 直接优化交易目标而非预测精度 | |
| 表示学习 | 学习标的的嵌入表示（如币的"叙事相似度"） | |

### 什么时候不值得

| 场景 | 为什么 |
|---|---|
| 日频因子数据 | 样本量太小（几年数据 = 几百到几千样本），树模型更合适 |
| 特征已经手工设计好 | 深度学习的优势是自动特征学习，你已经做了这一步 |
| 只有 20-50 个特征 | 树模型足够 |
| 需要可解释性 | 黑盒模型难以获得信任，出问题难排查 |

**一条实用判断：如果你的数据能装进一个 pandas DataFrame 并且行数 < 100 万，先用 LightGBM。**

## 二、序列模型选型

| 模型 | 特点 | 在金融上的表现 |
|---|---|---|
| LSTM / GRU | 经典循环网络 | 曾是主流，现在基本被替代 |
| **TCN（时序卷积）** | 因果卷积 + 膨胀卷积，并行训练 | **效果稳定，训练快，推荐先试** |
| Transformer | 自注意力，长距离依赖 | 需要大量数据；金融上容易过拟合 |
| **Patch-based Transformer**（PatchTST 类） | 把序列切成 patch，降低序列长度 | 时序预测的现代主流做法 |
| N-BEATS / N-HiTS | 纯前馈的时序分解 | 在通用时序基准上强，金融上需验证 |
| 状态空间模型（Mamba 类） | 线性复杂度处理长序列 | 长序列场景有潜力 |
| 混合模型（CNN + Attention） | | 常见的实用选择 |

### 关键提醒：因果性

**任何用于交易的模型必须是因果的**（只能用过去信息）。

常见陷阱：
- 双向 LSTM / 标准 Transformer 的全注意力 → 会看到未来。必须用因果掩码
- 全局归一化层（BatchNorm 用全数据统计）→ 泄漏
- 数据增强时的时间打乱

**规则：模型架构层面就要保证因果性，不要靠数据切分来"保证"。**

## 三、订单簿深度学习

这是深度学习在量化里最扎实的应用之一。

### 输入表示

```
输入形状：[时间步 T, 档位数 L × 2(买卖) × 2(价格,数量)]
例如：100 个时间步 × 10 档 × 2 边 × 2 = 100 × 40
```

或者用衍生特征：spread、微观价格、各档失衡、OFI 序列。

### 常见架构（DeepLOB 类）

```
1. 卷积层：捕捉档位间的局部结构（价格-数量对）
2. Inception 模块：多尺度时间特征
3. LSTM / TCN：时间依赖
4. 输出：短期方向分类（涨/平/跌）
```

### 现实挑战

| 挑战 | 说明 |
|---|---|
| 数据量 | L2 数据存储极大，需要专门的存储方案 |
| 标签定义 | "下一个 tick 涨跌"噪声极大；用中间价的平滑变化更好 |
| 类别不平衡 | 大部分时刻价格不变 |
| **预测有效但不可交易** | 预测准确率高，但价差吃掉全部利润 —— **最常见的失败模式** |
| 延迟要求 | 模型推理必须在微秒-毫秒级 |
| 训练成本 | 需要 GPU |

**关键警告**：订单簿预测的论文经常报告很高的准确率，但**几乎没有论文报告扣除价差和延迟后的净收益**。准确率 60% 的方向预测，如果每次交易要付一个价差，通常是负期望。

**判断**：这个方向对我来说是"知道它存在、理解它的原理"，但短期不做 —— 因为它需要 L2 数据基础设施 + 低延迟执行，两者都不是我当前的重点。

## 四、其他值得知道的方向

### 表示学习 / 嵌入

给每个标的学一个向量表示，捕捉"哪些币行为相似"。

用途：
- 替代人工的板块分类（人工分类是主观的、滞后的）
- 配对交易的候选筛选
- 组合的风险聚类

**这个方向在 crypto 里价值不错**，因为 crypto 的"板块"是叙事驱动的、变化快的，人工分类跟不上。

### 生成模型与合成数据

用 GAN / 扩散模型 / 时序生成模型生成合成价格路径，缓解样本不足。

| 潜在价值 | 风险 |
|---|---|
| 增加训练样本 | **分布失真**：生成的数据可能不保留关键的尾部特征 |
| 压力测试场景生成 | 如果生成器学到的是错的，你在错的数据上验证 |
| 数据增强 | |

**态度**：作为压力测试的场景生成器有价值；作为训练数据增强要非常小心。**不要用合成数据做最终验证。**

### 多任务与迁移学习

同时预测多个标的、多个周期，共享底层表示。

在 crypto 里有意义：单个币的数据少，但几百个币加起来数据多。参数共享能提升样本效率。

### 概率预测 / 分布预测

不只预测均值，预测整个分布（分位数回归、混合密度网络）。

**这个方向实用价值高**：交易决策需要的是分布信息（下跌 20% 的概率是多少），而不只是期望值。可以直接用于仓位决策和风险管理。

## 五、工程注意点

| 项 | 做法 |
|---|---|
| 因果性 | 架构层面保证；写测试验证 |
| 归一化 | 用滚动统计量，绝不用全样本 |
| 验证 | 仍然要用 purged/walk-forward，不能用随机切分 |
| 早停 | 用时序上正确的验证集 |
| 随机性 | 固定种子；但要跑多个种子看结果稳定性（**单个种子的结果不可信**） |
| 集成 | 多个种子/多个模型平均，通常显著改善稳定性 |
| 推理延迟 | 如果要实盘，测量推理时间；考虑量化/蒸馏 |
| 可解释性 | 至少做特征归因（Integrated Gradients / SHAP） |
| 模型监控 | 特征分布漂移检测、预测分布漂移检测 |

### 多种子的重要性

深度学习在低信噪比数据上的结果**方差极大**。同一配置换个随机种子，夏普可能从 1.5 变成 0.2。

**规则：任何深度学习结果必须报告多个种子（≥5）的分布，不能只报最好的那个。** 只报最好的种子是一种隐蔽的过拟合。

## 六、动手清单（等到阶段三之后）

- [ ] 用 TCN 做一个基线的收益率方向预测，与 LightGBM 对比
- [ ] 验证因果性：写测试确认模型不能访问未来时间步
- [ ] 跑 5 个随机种子，观察结果的方差（会让你对深度学习更谨慎）
- [ ] 实现分位数回归，输出预测分布而非点估计
- [ ] 把分布预测用于仓位决策，对比点预测
- [ ] 学习曲线：数据量 vs 性能，判断是否受样本量限制
- [ ] （如有 L2 数据）实现一个简化的订单簿模型，重点评估**扣成本后**的净收益
- [ ] 尝试标的嵌入学习，看聚类结果是否符合直觉的"板块"
