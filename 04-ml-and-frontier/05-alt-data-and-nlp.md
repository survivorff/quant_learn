# 05 · 替代数据与文本信号

> 传统市场的替代数据（卫星图、信用卡流水、招聘数据）贵得离谱。
>
> **crypto 的替代数据几乎全部免费，而且传统 quant 不熟悉它。这是我最实在的信息优势。**

---

## 一、crypto 替代数据全景

| 类别 | 数据 | 成本 | 我的熟悉度 |
|---|---|---|---|
| **链上交易** | 转账、swap、合约调用 | 免费（自建节点或公共 RPC） | 高 |
| **链上持仓** | 地址余额、持币时长、集中度 | 免费 | 高 |
| **协议数据** | TVL、借贷利用率、清算、治理 | 免费 | 中 |
| **DEX 数据** | 池深度、新池、异常交易 | 免费 | 高 |
| **场内衍生数据** | 资金费、OI、多空比、强平 | 免费（交易所 API） | 高 |
| **社媒** | 推文、Discord、Telegram、Reddit | 部分免费 | 中 |
| **开发活动** | GitHub commit、贡献者数 | 免费 | 高 |
| **新闻与公告** | 交易所公告、项目公告 | 免费 | 中 |
| **供给事件** | 解锁日历、质押/解押、增发销毁 | 免费 | 中 |
| **搜索/关注度** | 搜索趋势、社区规模 | 免费 | 低 |
| **跨市场** | 传统市场指数、美元指数、利率 | 免费 | 中 |

**起手优先级**：场内衍生数据（资金费/OI/强平）> 链上资金流 > 供给事件 > 社媒。

理由：前者数据质量最高、处理最简单、经济逻辑最清晰；社媒噪声最大、处理最难。

## 二、链上数据的因子化

### 资金流类

| 因子 | 构造 | 假设 |
|---|---|---|
| 交易所净流入 | 流入交易所 − 流出 | 净流入 = 潜在卖压 |
| 稳定币供应变化 | 铸造 − 销毁 | 供应增加 = 潜在买力 |
| 稳定币交易所余额 | | 待入场资金 |
| 桥资金流 | 跨链净流入 | 生态资金迁移 |
| 巨鲸转账 | 大额转账频率与方向 | 大资金动向 |

### 持仓结构类

| 因子 | 构造 | 假设 |
|---|---|---|
| 持币集中度 | Gini / top-N 占比 | 集中度高 = 操纵风险 |
| 长期持有者占比 | 按持币时长分组 | 长期持有者卖出 = 顶部信号 |
| 盈利地址占比 | 按成本基础估算 | 极端值对应情绪极端 |
| 新增地址数 | | 采用度增长 |
| 活跃地址数 | | 真实使用度 |

### 协议类

| 因子 | 假设 |
|---|---|
| 借贷利用率 | 高利用率 = 杠杆高 = 清算风险 |
| 借贷清算量 | 去杠杆压力 |
| TVL 变化 | 资金信心 |
| DEX 交易量 / CEX 交易量 | 市场结构变化 |

### 供给事件

| 因子 | 优势 |
|---|---|
| 解锁日历 | **完全可预测**，是罕见的"提前知道的供给冲击" |
| 质押解锁 | 同上 |
| 增发/销毁计划 | 同上 |

**解锁事件是我认为最值得先做的链上因子**：日历公开、事件明确、可用事件研究法严格验证。

## 三、链上数据的四个硬问题

### 1. PIT 正确性（最严重）

已在 [`02-strategy-zoo/06-crypto-native-strategies.md`](../02-strategy-zoo/06-crypto-native-strategies.md) 详述。核心：

**地址标签是"今天的知识"。** 用今天的交易所地址列表回测两年前的"交易所净流入"，是隐蔽的未来函数。

对策：
- 用带时间戳的标签快照
- 或只用不依赖标签的指标（活跃地址数、大额转账笔数、合约调用数）
- 明确记录哪些因子有 PIT 风险，在报告里标注

### 2. 地址聚类的不可靠性

一个实体有多个地址。启发式聚类（共同输入、找零地址模式）容易出错，且不同工具的结果不一致。

**建议**：避免依赖精细的实体级归因，用更粗粒度但可靠的指标。

### 3. 噪声与内部转账

交易所的冷热钱包归集、内部账务转移会污染"流入/流出"指标。

对策：过滤已知的内部地址对；用净额而非总额；对异常大额做人工核查。

### 4. 多链碎片化

同一资产在多条链上，需要合并视图。桥的资金流要正确归属。

对策：明确定义"资产的全链视图"，并接受它是不完整的。

## 四、社媒与文本情绪（预期要放低）

### 为什么难

| 问题 | 说明 |
|---|---|
| 信噪比极低 | 大量无意义内容 |
| **机器人与刷量** | crypto 社媒的机器人比例很高 |
| **因果方向** | 情绪跟随价格，还是价格跟随情绪？**通常是前者** |
| 重复报道 | 同一件事被报道几十次，测量的是报道量不是新信息 |
| 数据获取限制 | 平台 API 越来越贵/受限 |
| 样本偏差 | 只能抓到公开的一部分 |

### 因果方向问题最关键

大多数"社媒情绪因子"实际上是价格的滞后指标：价格涨了大家兴奋，然后你测出"情绪与未来收益正相关"（因为动量）。

**检验方法**：
1. 对情绪因子做**价格动量中性化**（回归掉动量后看残差还有没有 IC）
2. 检验 Granger 因果性（双向）
3. 只用"新信息"（新颖度过滤后）

**如果中性化掉动量之后情绪因子失效，说明它只是动量的代理，没有独立价值。** 这是必做的检验。

### 相对可靠的文本信号

| 信号 | 为什么相对可靠 |
|---|---|
| 结构化事件抽取（上币/解锁/安全事件） | 事实性，不是情绪 |
| 官方公告的分类与时间戳 | 权威来源 |
| 治理提案的内容与投票 | 有实际影响 |
| 开发活动（GitHub） | 客观、难伪造 |
| 极端情绪的**反向**用法 | 极端一致的乐观往往对应顶部 |

**我的判断**：先做结构化事件抽取（事实性信号），社媒情绪打分放到最后，且预期要低。

## 五、替代数据的通用工作流

```
1. 数据获取（免费源优先，注意速率限制与 ToS）
2. 落地到 raw 层（带 ingest_time，永不覆盖）
3. 清洗与去噪（过滤已知噪声、去重、新颖度过滤）
4. 对齐到交易时间轴（注意时区、发布延迟）
5. 因子化（构造可测量的数值）
6. **PIT 检查**（标注哪些字段有 PIT 风险）
7. 标准化 + 中性化（对价格动量、对 BTC beta）
8. 走标准因子评估流水线
9. 特别检验：与价格动量的正交性、因果方向
```

### 第 4 步（时间对齐）最容易出错

替代数据有"发布延迟"：链上数据要等区块确认，公告有发布时刻，社媒有抓取延迟。

**规则：因子的时间戳必须是"我最早能知道这个信息的时刻"，不是"事件发生的时刻"。**

例如：区块在 T 时刻产生，但你的节点在 T+3s 才同步到 → 因子时间戳用 T+3s。忽略这个延迟在高频上是致命的。

## 六、我的实施优先级

| 优先级 | 数据 | 理由 |
|---|---|---|
| 1 | 资金费 / OI / 强平（交易所 API） | 免费、干净、经济逻辑清晰、我最懂 |
| 2 | 代币解锁日历 | 可预测的供给冲击，事件研究法可严格验证 |
| 3 | 交易所资金净流（简化版，只用大额转账） | 避开精细标签的 PIT 问题 |
| 4 | 借贷协议利用率与清算量 | 杠杆水平的直接度量 |
| 5 | 开发活动 | 客观，长周期因子 |
| 6 | DEX 流动性与新池 | 早期信号，但噪声大 |
| 7 | 社媒情绪 | 最后做，预期最低 |

**先做 1-2 两项，把因子评估流水线跑通，再逐步加。** 不要一开始就想建一个全量链上数据仓库 —— 那是几个月的工程，而 1-2 两项一周就能出结果。
