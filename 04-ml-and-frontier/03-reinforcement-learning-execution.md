# 03 · 强化学习：真实位置是执行优化

> RL 在量化里被严重误用。**它不适合做方向预测，但很适合做执行和仓位管理。**
>
> 判断标准很简单：RL 需要大量交互样本和明确的奖励信号。执行问题满足这两点，方向预测不满足。

---

## 一、为什么 RL 不适合方向预测

| 问题 | 说明 |
|---|---|
| **样本效率极低** | RL 通常需要百万级交互。日频数据一年才 365 个样本 |
| 奖励信号噪声极大 | 单笔交易的盈亏几乎全是噪声，agent 学到的是运气 |
| 无法真正"交互" | 只能在历史数据上回放，agent 的行为不影响环境（与真实市场不同） |
| 过拟合严重 | 高容量策略网络 + 低信噪比 = 记住历史 |
| 不可解释 | 出问题不知道为什么 |
| 评估困难 | RL 的评估本身就是难题，加上金融的验证问题，双重困难 |

**一个残酷的现实检验**：把 RL agent 在纯随机数据上训练，它也会"学到"一个看起来有效的策略。如果你的 RL 结果和随机数据上的结果分布相似，说明你什么也没学到。

**规则：做任何 RL 实验前，先在随机游走数据上跑一遍作为零假设基线。**

---

## 二、RL 适合的三个场景

### 1. 最优执行（最扎实的应用）

问题：要在 T 时间内买入 Q 数量，怎么拆单使总成本最小？

| 为什么适合 RL |
|---|
| 序列决策问题（每一步的决策影响后续状态） |
| **奖励明确**：执行成本 vs 基准价（VWAP/到达价） |
| **样本量大**：每笔执行都是一个 episode，高频下样本充足 |
| 奖励噪声相对小（成本比收益容易度量） |
| 有明确的经典基线（TWAP/VWAP/Almgren-Chriss）可对比 |

状态空间：剩余数量、剩余时间、当前价差、深度、近期价格动量、订单流失衡
动作空间：本步下多少量、用市价还是限价、限价挂多深
奖励：负的执行成本（相对基准）

**这是我认为最值得投入的 RL 方向**，因为它有明确的评估标准、充足的样本、且改善直接变成收益（省下的成本就是利润）。

### 2. 做市报价

问题：如何动态调整双边报价以平衡成交量与库存风险？

| 为什么适合 |
|---|
| 序列决策 + 库存状态 |
| 高频，样本量大 |
| 奖励 = PnL − 库存风险惩罚，可以设计 |
| 有经典基线（Avellaneda-Stoikov）可对比 |

难点：需要高质量的订单簿模拟环境（含队列位置、延迟、逆向选择），否则 agent 会学到"利用模拟器的 bug"。

### 3. 仓位管理 / 组合再平衡

问题：给定信号，怎么调整仓位以最大化风险调整后收益？

比方向预测靠谱一些，因为：
- 动作空间是连续的仓位，不是离散的买卖
- 奖励可以设计成风险调整后的（如对数财富增长、夏普）
- 与 Kelly 公式等经典解可对比

但仍然要小心过拟合。

## 三、算法选型

| 算法 | 类型 | 适用 |
|---|---|---|
| Q-learning / DQN | 值函数，离散动作 | 简单执行问题（离散化下单量） |
| **PPO** | 策略梯度，稳定 | **通用首选**，连续动作 |
| SAC | off-policy，样本效率高 | 样本有限时更好 |
| TD3 | 连续控制 | |
| 离线 RL（CQL / IQL 等） | 只用历史数据，不需要在线交互 | **金融场景的天然选择**（无法在线试错） |
| 模仿学习 / 行为克隆 | 从专家策略学习 | 冷启动：先模仿 TWAP，再优化 |

### 离线 RL 值得单独说

金融场景无法真正"在线试错"（每次试错都花真钱）。离线 RL 专门处理"只有固定数据集"的情况。

但离线 RL 有个核心难题：**分布偏移** —— agent 想尝试的动作在数据集中没有出现过，价值估计不可靠。这在执行问题上相对好处理（因为可以用模拟器生成），在方向预测上是致命的。

### 实用的起手方式

```
1. 先实现经典基线（TWAP / Almgren-Chriss / A-S）
2. 用行为克隆让 agent 模仿基线（验证环境和训练流程正确）
3. 再用 PPO 在基线之上优化
4. 严格对比：RL 是否真的打败了基线？打败了多少？在样本外还打败吗？
```

**如果 RL 打不过 TWAP，就用 TWAP。** 复杂度必须换来实质改进。

## 四、环境设计（成败关键）

RL 的结果质量 ≈ 环境的真实度。**环境有 bug，agent 会精准地利用它。**

| 要素 | 必须建模 |
|---|---|
| 市场冲击 | 你的下单影响价格（否则 agent 会学到"一次全下"） |
| 延迟 | 决策到执行的时间 |
| 部分成交 | 限价单不一定全成 |
| 队列位置 | 做市场景必须 |
| 成本 | 手续费、价差 |
| 拒单 | 精度、限流 |
| 库存约束 | 硬上限 |

### 最常见的 RL 环境 bug

**没建模市场冲击** → agent 发现"一次性下 100 倍的量"能获得最好的即时价格 → 学出一个在实盘上灾难性的策略。

**规则：设计好环境后，先用极端策略测试它。** 如果"一次全下"或"永不下单"能拿到不合理的高奖励，环境有 bug。

---

## 五、奖励设计

| 奖励 | 问题 |
|---|---|
| 累计 PnL | 鼓励高风险；方差大，学习不稳定 |
| 夏普 | 非马尔可夫（依赖整段历史），难以直接优化 |
| **差分夏普 / 增量风险调整收益** | 可分解到单步，实用 |
| 对数财富增长 | 与 Kelly 一致，理论优雅 |
| PnL − λ·风险惩罚 | 实用，λ 可调 |
| 相对基准的超额（执行场景） | **执行问题的标准做法** |

关键原则：**奖励要与你真正想优化的目标对齐**。如果你在乎回撤，奖励里必须有回撤惩罚，否则 agent 不会关心它。

## 六、验证：RL 的验证比监督学习更难

| 要求 | 说明 |
|---|---|
| 时序切分 | 训练/验证/测试严格按时间，不能随机 |
| **多随机种子** | RL 的种子方差极大，必须报告 ≥10 个种子的分布 |
| 随机数据基线 | 在随机游走上训练，作为零假设 |
| 经典基线对比 | 必须打败 TWAP/A-S 等 |
| 样本外多时段 | 不同市场状态下都要测 |
| 敏感性分析 | 环境参数（延迟、冲击系数）变化时是否稳健 |
| 行为可解释性 | 看 agent 学到了什么策略；如果无法解释，不要上实盘 |

**"行为可解释性"这条很重要**：好的 RL 执行 agent 学到的策略通常可以被人理解（如"深度厚时多下、价差宽时少下"）。如果 agent 的行为完全无法解释，大概是在拟合噪声。

## 七、我的判断与路线

| 方向 | 判断 | 时间 |
|---|---|---|
| RL 做执行优化 | ✅ 值得做，但排在实盘系统跑通之后 | 阶段四 |
| RL 做做市报价 | ⚠️ 需要高质量订单簿模拟器先建好 | 阶段四之后 |
| RL 做仓位管理 | ⚠️ 可以试，但优先用 Kelly/vol targeting 等有理论基础的方法 | 低 |
| RL 做方向预测 | ❌ 不做 | — |

**现实的顺序**：先把执行做对（用经典算法 + TCA 优化），确认执行成本是瓶颈之后，再考虑用 RL 进一步优化。**不要在还没有实盘 TCA 数据的时候就上 RL。**
