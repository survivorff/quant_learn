## 一、需要的线性代数（够用清单）

| 概念 | 在量化里做什么 |
|---|---|
| 矩阵乘法 / 向量化 | 组合收益 = 权重向量 × 收益矩阵；一切性能优化的基础 |
| 协方差矩阵 Σ | 组合风险 `σ²_p = wᵀΣw`，一切组合优化的核心输入 |
| 特征值 / 特征向量 | PCA、风险因子分解、判断矩阵是否病态 |
| SVD | 降维、去噪、伪逆 |
| 正定性 | Σ 必须正定，否则优化器会给出荒谬的解 |
| 矩阵求逆 / 求解线性系统 | 最优权重解析解；**永远不要真的求逆**，用 `solve` |

### 协方差矩阵的三个陷阱

这是理论与实务差距最大的地方：

1. **维数灾难**：N 个资产需要估计 N(N+1)/2 个参数。50 个资产 = 1275 个参数。如果只有 500 天数据，估计误差会大到让优化结果毫无意义。
   - 经验法则：观测数 T 至少要 10×N，理想 100×N

2. **病态与不稳定**：样本协方差矩阵最小特征值往往接近 0，求逆后误差被放大几个数量级。结果是优化器输出极端权重（+300% / -280% 这种）。

3. **相关性在危机中失效**：历史 Σ 描述的是平静期。真正需要分散化时，相关性趋于 1。

### 修复手段

| 方法 | 思路 |
|---|---|
| Ledoit-Wolf 收缩 | 把样本协方差往结构化目标（如对角矩阵）收缩，**最常用，效果好且简单** |
| 随机矩阵理论去噪 | 用 Marchenko-Pastur 分布识别噪声特征值并压平 |
| 因子模型 | 用少数因子（如市场、动量、规模）重构 Σ，参数量骤降 |
| 层次聚类（HRP） | 完全绕过矩阵求逆，用树结构分配权重 |
| EWMA 协方差 | 给近期数据更高权重，响应更快 |

**实务建议**：直接用 `sklearn.covariance.LedoitWolf`，或者用 HRP。手写样本协方差 + 求逆 = 自找麻烦。

### PCA 在量化里的位置

- 提取市场共同因子（第一主成分通常就是"市场"）
- 统计套利：对残差（去掉主成分后）做均值回归 —— 这是经典 statarb 的核心
- 降维：把 100 个相关因子压成 10 个正交因子
- **注意**：主成分没有经济含义，且成分构成会随时间漂移。用在风险管理上比用在 alpha 上更靠谱

## 二、优化：组合构建的数学

### 经典均值-方差（Markowitz）

```
最小化   wᵀΣw
约束     wᵀμ ≥ r_target,  Σw = 1,  （可选）w ≥ 0
```

理论优雅，实务上**几乎不能直接用**，原因：

1. 对 μ（预期收益）的估计误差极度敏感 —— 输入误差 1% 可能让权重变化 100%
2. 输出极端集中的权重
3. 需要 Σ 的逆，放大估计误差

> 有个经典结论：等权重组合在样本外经常打败均值-方差最优组合。这不是说优化没用，是说**输入的估计误差比优化的收益更大**。

### 实务中更稳健的替代方案

| 方法 | 需要什么输入 | 特点 |
|---|---|---|
| **等权（1/N）** | 无 | 基线，别小看它 |
| **风险平价（Risk Parity）** | 只需 Σ | 每个资产贡献相同风险，不需要预测收益 |
| **逆波动率加权** | 只需 σ | 风险平价的简化版，极其实用 |
| **HRP（层次风险平价）** | 只需 Σ | 用聚类树分配，不求逆，López de Prado 提出 |
| **最小方差** | 只需 Σ | 不需要预测收益，但可能过度集中在低波动资产 |
| **波动率目标（vol targeting）** | 只需预测 σ | 单策略层面最实用的风险控制 |
| Black-Litterman | Σ + 主观观点 | 把先验和观点结合，缓解 μ 估计问题 |
| 带正则化的 MVO | Σ + μ + 惩罚项 | 加 L1/L2 惩罚抑制极端权重 |

**核心洞察：能不预测收益就不预测收益。** 只依赖 Σ 的方法（风险平价、HRP、最小方差）在样本外远比依赖 μ 的方法稳健，因为协方差比预期收益容易估得多。

### 凸优化工具

- `cvxpy`：声明式写约束，可读性最好，适合研究阶段
- `scipy.optimize`：够用，灵活
- `riskfolio-lib` / `skfolio`：组合优化专用库，内置各种风险度量与约束

必须加的实务约束：
- 单标的权重上限（防集中）
- 换手率约束或交易成本惩罚项（否则优化器会给出天天大换手的解）
- 杠杆上限
- 流动性约束（权重不能超过该标的日均成交量的某个比例）

## 三、数值计算的工程注意点

来自后端工程的直觉在这里很有用：

| 问题 | 做法 |
|---|---|
| 求逆 | 用 `np.linalg.solve` 或 Cholesky 分解，不要 `inv` |
| 数值稳定 | 检查条件数 `np.linalg.cond`，> 1e10 就要警惕 |
| 正定性 | 优化前检查最小特征值，必要时加 `εI` 或做 nearest-PD 修正 |
| 精度 | PnL 累加用 `Decimal` 或整数最小单位（satoshi/wei 思维），float 累加会漂 |
| 性能 | 先向量化，不够再上 `numba`，最后才考虑 Rust/C++ |
| 可复现 | 固定随机种子，记录库版本 |

**float 精度那条对交易系统特别重要**：仓位与资金计算用浮点累加，跑几万笔之后会和交易所对不上账。用整数最小单位存储，这是我在后端做资金系统的老经验，在这里同样适用。
