# 03 · 做市

> 做市不是"在盘口两边挂单赚价差"这么简单。它的本质是：**为了赚取流动性溢价，主动承担库存风险和逆向选择风险。**
>
> 工程门槛最高的策略族，但也最匹配我的后端能力。定位：**先做模拟理解机制，工程能力够了再上小额实盘。**

---

## 一、做市商的盈亏结构

```
做市收益 = 价差收入 + maker 返佣 − 逆向选择损失 − 库存风险损失 − 技术/运维成本
```

| 项 | 说明 |
|---|---|
| 价差收入 | 每完成一次"买低卖高"的往返，赚一个价差 |
| **maker 返佣** | 部分交易所 maker 是负费率（交易所付你钱）。**这是很多做市策略的真实利润来源** |
| 逆向选择损失 | 你的挂单在价格不利变动时优先成交。这是最主要的亏损来源 |
| 库存风险损失 | 单边成交后持有裸露仓位，价格不利变动 |
| 技术成本 | 延迟、稳定性、开发维护 |

### 核心洞察：逆向选择是主要敌人

你的买单成交，意味着**有人愿意在那个价格卖给你**。在信息不对称的市场里，这经常意味着他知道价格要跌。

所以做市商的挂单是"被选择"的，而选择你的人平均而言是对的。这就是逆向选择。

**应对的两个手段**：
1. **拉宽价差**（用更高的补偿覆盖损失）—— 但会降低成交量
2. **更快撤单**（在信息到达前撤掉）—— 这就是延迟竞赛的根源

个人做市能不能活，取决于能否在这两者间找到可行区间：**在流动性差、竞争少的标的上，用较宽的价差 + 可接受的延迟活下来。**

## 二、Avellaneda-Stoikov 模型（必须理解的基准）

学术界最经典的做市模型，把库存风险显式建模。

### 核心思想

1. **计算保留价格（reservation price）**：不是中间价，而是根据当前库存调整后的"你认为的公允价"

```
r(s, q, t) = s − q·γ·σ²·(T − t)
```

- `s` = 中间价
- `q` = 当前库存（正为多头）
- `γ` = 风险厌恶系数
- `σ` = 波动率
- `(T−t)` = 剩余时间

**直觉**：持有多头库存（q > 0）时，保留价格低于中间价 → 报价整体下移 → 更容易卖出、更难买入 → 库存自动回归中性。

这个"库存偏斜（inventory skew）"是模型最有价值的部分。

2. **计算最优价差**：

```
δ_total = γ·σ²·(T − t) + (2/γ)·ln(1 + γ/k)
```

- 第一项：库存风险补偿（波动率越高、时间越长，价差越宽）
- 第二项：与订单到达强度 `k` 相关（成交越容易，价差可以越窄）

3. **报价**：`bid = r − δ/2`，`ask = r + δ/2`

### 实务修正（原模型的问题）

| 问题 | 修正 |
|---|---|
| 假设无手续费 | 必须把手续费/返佣加入价差计算 |
| 假设连续报价 | 实际有 tick size 和最小变动 |
| `T` 是有限期限（原模型是做市到收盘） | crypto 24/7，需改成无限期版本或用滚动窗口 |
| 未建模队列位置 | 实际成交概率取决于排队 |
| 未建模跳变风险 | crypto 会插针，需要硬性库存上限和熔断 |
| 波动率是常数 | 需要实时波动率估计 |
| 未用订单簿信息 | 用 microprice 替代 mid price 是明显改进 |
| 未建模趋势 | 单向趋势中会持续逆向成交，需要趋势过滤器 |

**实操建议**：把 A-S 当作**框架**（保留价格 + 库存偏斜 + 动态价差），而不是照抄公式。真正的实现是：

```
公允价 = microprice（或多所加权）
报价中心 = 公允价 − 库存偏斜项
半价差 = max(最小价差, 波动率项 + 成本项 + 竞争调整)
最终报价 = 报价中心 ± 半价差
```

## 三、做市系统的必要组件

这一节是我的工程主场：

| 组件 | 职责 | 关键点 |
|---|---|---|
| 行情接入 | WS 订阅深度/成交，维护本地订单簿 | 序列号校验、断线重连、延迟监控 |
| 公允价引擎 | 计算 microprice / 多所加权价 | 用多个交易所的价格提高抗操纵性 |
| 报价引擎 | 计算目标报价与数量 | 库存偏斜、波动率自适应 |
| 订单管理（OMS） | 维护挂单状态，决定改价/撤单 | **幂等性**、状态机、改价节流 |
| 库存管理 | 跟踪持仓，触发对冲或强制平衡 | 硬上限 + 软目标 |
| 对冲模块 | 在另一个市场对冲 delta | 跨所/现货-永续对冲 |
| 风控 | 库存上限、亏损熔断、异常检测 | **独立于策略逻辑，能单独杀掉策略** |
| 对账 | 本地状态 vs 交易所状态 | 定期全量对账，发现不一致立刻停 |
| 监控 | 延迟、成交率、库存、PnL、错单 | 实时告警 |

### 我的后端经验直接可用的地方

- **订单状态机 + 幂等**：订单的 new/partial/filled/canceled 状态转换，重复消息去重 —— 这就是分布式系统的消息处理
- **本地簿与远端一致性**：典型的状态同步问题，序列号 + 定期全量校验
- **改价节流**：限流与背压，避免触发交易所限流
- **对账**：资金系统对账的标准套路
- **可观测性**：指标、日志、告警的完整链路

**这些是纯数学背景的人做不好的地方。这就是我的护城河。**

## 四、库存管理（做市的生死线）

| 机制 | 说明 |
|---|---|
| 库存偏斜 | 库存越偏离目标，报价越偏移，自动回归 |
| 硬上限 | 绝对不允许超过的库存，触及则停止单边报价 |
| 主动对冲 | 库存超过阈值时主动 taker 平掉一部分（付成本换风险降低） |
| 对冲腿 | 在现货/另一个所反向持仓，做 delta 中性 |
| 时间衰减 | 持仓时间过长强制减仓 |

### 关键权衡

主动对冲要付 taker 成本，但能避免尾部风险。**新手常见错误：为了省手续费不对冲，然后被一次单边行情打穿。**

规则：**库存风险的期望损失 > 对冲成本时，必须对冲。** 高波动时段这个阈值要下调。

## 五、什么情况下个人做市可行

诚实评估：

| 条件 | 说明 |
|---|---|
| ✅ 流动性中等、竞争较少的标的 | 主流币的做市被专业机构垄断，别去 |
| ✅ maker 返佣为负的交易所 | 返佣本身就是收益，降低对 alpha 的要求 |
| ✅ 较宽的价差容忍（不追求最高成交量） | 用宽价差换取对延迟的低要求 |
| ✅ 有对冲通道（现货/其他所） | 降低库存风险 |
| ✅ 工程实力强，系统稳定 | **这是我的优势** |
| ❌ 主流币盘口一档竞争 | 打不过机构 |
| ❌ 没有延迟优化就做高频报价 | 会被系统性逆向选择 |
| ❌ 没有独立风控就上实盘 | 一次 bug 就能亏光 |

### 现实的路径

1. 先做**订单簿模拟回测**（`lab-04`），理解库存风险和逆向选择的量级
2. 在模拟盘跑，验证系统稳定性（这一步至少 1 个月）
3. 选一个流动性中等的标的，用极小仓位实盘
4. 逐步优化：先稳定性，再成交率，最后才是收益率

**别跳步。做市系统的 bug 是最贵的 bug**，因为它在高频下单，错误会被快速放大。
