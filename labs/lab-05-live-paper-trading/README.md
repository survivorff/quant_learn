# lab-05: 模拟盘与实盘系统

> **这是分界线**：从"回测选手"变成"交易者"。
>
> 也是我最能发挥工程优势的一个 lab（幂等、对账、监控、故障处理），以及第三个作品级项目。

**状态**：未开始
**依赖**：lab-02（策略代码复用）
**对应知识**：[`05-risk-and-portfolio/04-live-trading-ops.md`](../../05-risk-and-portfolio/04-live-trading-ops.md)、[`06-engineering`](../../06-engineering/)

---

## 解决什么问题

回测和实盘之间有一条鸿沟：延迟、部分成交、拒单、断线、状态不一致、交易所异常。

这个 lab 要建一个能**7×24 稳定运行、状态永远正确、出问题能自己保护自己**的系统。

出口标准是一句话：**我出差一周不看它，它能自己活下来。**

## 核心组件

### 行情与状态

- [ ] WS 订阅 + REST 补齐
- [ ] 本地订单簿维护（序列号校验 + 断裂重同步）
- [ ] 断线自动重连 + 重新订阅 + 补齐断线期数据
- [ ] 数据新鲜度检查（过期数据不用于决策）

### 策略与执行

- [ ] **目标仓位模式**接口（幂等、重启安全）+ 死区
- [ ] 跨策略仓位聚合器
- [ ] 执行引擎：post-only 挂单 + 超时转 IOC
- [ ] **不使用裸市价单**（用 Limit IOC + 价格保护）
- [ ] 拆单（单笔超过深度阈值时）

### 订单管理（工程重点）

- [ ] 完整状态机，**含 UNKNOWN 状态**
- [ ] `client_order_id` 生成与解析
- [ ] **先落盘，再发请求**
- [ ] `safe_place_order` + `resolve_unknown`（超时先查询，不直接重试）
- [ ] 成交回报幂等（`trade_id` 去重 + **累计量同步**而非增量累加）
- [ ] 消息乱序守卫（用交易所更新序号）
- [ ] 限流令牌桶，**为撤单预留额度**
- [ ] 改价节流

### 风控（独立且不可绕过）

- [ ] 分层限额（账户/交易所/策略/标的/单笔）
- [ ] **`max_daily_trades`**（防 bug 无限下单）
- [ ] 三级熔断（减仓 / 停止开仓 / 全平停机）
- [ ] 风控状态持久化（重启后日内亏损、交易计数不丢）
- [ ] 所有减仓单加 `reduce-only`
- [ ] fail-safe：风控检查失败则拒绝下单

### 对账

- [ ] 三源对账（意图 / 本地 / 交易所）
- [ ] 多频率：挂单每分钟、持仓每分钟、余额每 5 分钟、成交明细每日
- [ ] 孤儿单 / 幽灵单检测与处理
- [ ] **外部变更识别**（强平 / ADL / 手动操作）—— 不要试图"纠正"
- [ ] 显著不一致 → **停止下单，人工介入**（不自动修复）

### 监控与告警

- [ ] 心跳、行情延迟、下单成功率、拒单率、延迟 P99
- [ ] 持仓偏差、保证金充足率、敞口
- [ ] 日内 PnL、当前回撤
- [ ] 状态一致性
- [ ] **告警分级 + 去重 + 可操作内容**
- [ ] **故意触发每一类告警，验证都能收到**

### 精度与账务

- [ ] 金额用**整数最小单位**（不用 float 累加）
- [ ] 下单数量向下取整、买价向下、卖价向上
- [ ] 最小下单量与最小名义价值检查
- [ ] 余额留缓冲（如 99%）

### 复盘

- [ ] **PnL 归因**（信号 / 执行成本 / 资金费 / 执行偏差）
- [ ] TCA 记录（决策价、下单价、成交价、下单时 BBO 与深度）
- [ ] 每日复盘报告自动生成
- [ ] 情绪记录（见 [`journal/trade-journal-template.md`](../../journal/trade-journal-template.md)）

## 安全（不可妥协）

- [ ] API 权限最小化：**提币权限关闭**
- [ ] IP 白名单
- [ ] 密钥在 keychain / KMS，不在配置文件、不在 git
- [ ] 只读监控账号与交易账号分离
- [ ] 测试网与生产环境密钥物理隔离
- [ ] 定期提币演练

---

## 怎么验证正确性

### 故障注入（11 项，全部必须通过）

- [ ] 拔网线（WS 断线）
- [ ] 交易所返回限流错误
- [ ] 交易所返回拒单
- [ ] **下单请求超时但实际成功**（最重要的一项）
- [ ] 成交回报丢失
- [ ] 重复的成交回报
- [ ] 乱序的回报
- [ ] `kill -9`（验证重启恢复）
- [ ] 磁盘写满
- [ ] 时钟跳变
- [ ] 交易所返回意外字段/格式

每一项都要验证系统行为**符合预期**，而不是"崩了"或"静默出错"。

### 其他验证

- [ ] 单元测试：成本、仓位、PnL、信号对齐
- [ ] 状态机测试：全部合法/非法转换
- [ ] 幂等测试
- [ ] 重启恢复测试
- [ ] 行情录制回放的集成测试
- [ ] **上线检查清单**全部勾选（见 [`05-risk-and-portfolio/04`](../../05-risk-and-portfolio/04-live-trading-ops.md)）

## 出口标准

| 标准 | 目标 |
|---|---|
| 在线率 | > 99% |
| 连续无干预运行 | ≥ 30 天（模拟）+ 60 天（实盘） |
| 错单 / 状态不一致 | 0（非 0 必须有复盘和修复） |
| 实盘-回测偏差 | 可解释，来源明确 |
| **出差一周测试** | 通过 |
