## 解决什么问题

后续所有回测、因子研究、策略验证都依赖数据。如果数据有缺失、有错误、有未来函数（PIT 问题），上层所有结论都不可信。

这个 lab 要建立一个**可信、可复现、可增量更新**的数据基础。

## 设计要点

### 三层存储

| 层 | 内容 | 规则 |
|---|---|---|
| `raw/` | 原始 API 响应，一字不改 | **只追加，永不修改**，带 `ingest_time` |
| `clean/` | 标准化后 | 统一 schema、UTC、统一精度、异常标记 |
| `feature/` | 计算好的因子 | 可重算可删除，用于加速 |

**raw 层的价值**：清洗逻辑有 bug 时能重建，不用重新下载（可能已拿不到）。

### 分区方案

```
clean/klines/symbol=BTCUSDT/interval=1h/year=2025/month=01/data.parquet
```

按 symbol + interval + 时间分区，让"只读某标的某段时间"的查询能做分区裁剪。

### 数据质量校验清单

- [ ] 时间连续性（按周期生成完整时间轴，找缺失 bar）
- [ ] 重复记录（按 symbol + timestamp 去重）
- [ ] OHLC 逻辑（`low ≤ min(o,c) ≤ max(o,c) ≤ high`）
- [ ] 零/负值
- [ ] 极端跳变（> N 倍标准差，人工确认）
- [ ] 成交量异常（长期 0 或突增数量级）
- [ ] 时区（必须全部 UTC 带 tz）
- [ ] 精度一致性（符合合约规格）
- [ ] 资金费完整性（每个结算周期都有）
- [ ] **区分"缺失"和"零"**（用不同标记，不要都填 0）

### 处理原则

| 情况 | 处理 |
|---|---|
| 少量孤立缺失 | `ffill` 但**打标记** |
| 大段缺失 | 不填充，标记为不可交易区间 |
| 明显脏数据 | 修正并记录修正日志，保留 raw |
| 不确定 | **保守：标记不可用** |

**永远不要静默填充。**

## 怎么验证正确性

- [ ] 数据质量校验全部通过，输出报告
- [ ] 跨源交叉验证：两个交易所同标的的价格差异在合理范围
- [ ] 幂等测试：同一时间段重跑两次，数据不重复
- [ ] 断点续传测试：中途杀掉进程，重启后能续上
- [ ] PIT 测试：`as_of_time` 查询只返回该时刻之前采集的数据
- [ ] **幸存者偏差对比实验**：只用现存标的 vs 含已下架标的，量化差异

最后一条是这个 lab 最有价值的产出之一。
