```

```

**这是我最重要的学习对象** —— 它把"研究到实盘同一套代码"这个理念落地了，而这正是我要做的事。

## 六、Crypto 特有

| 仓库/工具 | 用途 |
|---|---|
| **ccxt** | 多交易所统一接口（数据采集与下单的事实标准） |
| 各交易所官方 SDK | 延迟敏感场景用原生 API 而非 ccxt |
| web3.py / ethers 类库 | 链上交互 |
| 链上索引方案（自建或托管） | 链上数据管道 |
| awesome-crypto-trading-agents 类清单 | 生态概览（[参考](https://github.com/shakeebshaan/awesome-crypto-trading-agents)，内容已改写以符合许可要求） |

### 使用 ccxt 的注意点

- ✅ 适合：历史数据采集、低频下单、多所统一逻辑
- ❌ 不适合：延迟敏感的场景（有额外抽象开销）
- ⚠️ 注意：ccxt 的统一化会隐藏交易所的重要差异（订单类型语义、精度规则）。**关键逻辑要读原生文档确认**

## 九、读源码的方法

不要从 main 函数开始逐行读。用这个顺序：

```
1. 读 README 和架构文档（建立心智模型）
2. 找到核心数据结构（Order、Position、Event 定义）
3. 追一条完整链路（一笔订单从创建到成交）
4. 看它怎么处理边界情况（超时、拒单、部分成交）← 这里价值最大
5. 看它的测试（测试暴露了作者担心什么）
6. 写差异笔记（它和我的实现有什么不同，为什么）
```

**第 4 和第 5 步是精华。** 边界情况的处理和测试用例，是"作者踩过的坑"的直接记录。

笔记放在 [`notes/`](../notes/)。
