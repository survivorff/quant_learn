# 数据源

> crypto 的核心优势：**核心数据全部免费**。这一页记录数据从哪来、有什么坑。
>
> 原则：先把免费数据用尽，再考虑付费。前 6 个月不投入超预算的数据费用。

---

## 一、场内数据（交易所 API，免费）

### 数据类型与获取方式

| 数据 | 获取方式 | 历史深度 | 注意 |
|---|---|---|---|
| K 线（OHLCV） | REST 批量 + WS 实时 | 通常几年 | 分页限制、限流 |
| 逐笔成交 | REST + WS | 有限（可能只几天到几月） | **历史逐笔往往拿不到全量，要尽早开始采集** |
| L2 深度快照 | WS 增量 + REST snapshot | **通常无历史** | **必须自己实时采集，错过就没有** |
| 资金费率 | REST | 完整历史 | 各所结算周期不同 |
| 未平仓量（OI） | REST | 有限历史 | 尽早开始采集 |
| 标记价 / 指数价 | WS / REST | 有限 | |
| 强平数据 | WS 推送 | **通常无历史** | 必须实时采集 |
| 多空持仓比 | REST | 有限 | |
| 合约规格 | REST | 当前值（会变） | **要做快照版本化** |
| 上下币公告 | 公告页 / API | 需自己整理 | 幸存者偏差处理的关键 |
| 期权链与 IV | REST / WS | 有限 | |

### 关键行动：立刻开始采集"无历史"的数据

| 数据 | 为什么急 |
|---|---|
| L2 深度 | 完全没有历史，今天不采就永久缺失 |
| 逐笔成交 | 历史有限 |
| 强平数据 | 无历史 |
| OI | 历史有限 |
| 合约规格快照 | 变更后旧值就丢了 |

> **这是 lab-01 最紧急的部分。** 知识可以以后学，数据错过就补不回来。哪怕采集器还很粗糙，也要先跑起来往硬盘里存。

## 二、数据质量的坑

| 坑 | 说明 | 应对 |
|---|---|---|
| 交易所修订历史 K 线 | 你现在下的与当时看到的不同 | 双时间戳 + raw 层不可变 |
| 小交易所刷量 | 成交量可能是假的 | 交叉验证；只用主流所 |
| 幌骗（spoofing） | 深度可能是虚假挂单 | 结合成交数据判断 |
| 时间戳语义不一致 | 有的是开始时间，有的是结束时间；有的是撮合时间，有的是入队时间 | 逐个所验证并记录 |
| 精度变更 | 合约的价格/数量精度会调整 | 快照版本化 |
| 单位不一致 | 有的所用张，有的用币，有的用 USD | 统一到统一口径 |
| 时区 | 必须全部 UTC | 强制校验 |
| 限流被封 | 高频轮询会被封 IP | 用 WS，令牌桶 + 退避 |
| 分页边界重复/遗漏 | 分页逻辑的经典 bug | 幂等 + 完整性校验 |
| 下架标的的数据消失 | 下架后可能拿不到历史 | 尽早采集并归档 |

### 一条重要纪律

**每接一个新数据源，先做一次"跨源交叉验证"**：同一标的、同一时间段，从两个来源取数据对比。差异超过阈值就要搞清原因。

## 三、链上数据

| 方式 | 成本 | 适用 |
|---|---|---|
| 公共 RPC | 免费 | 起步、低频查询 |
| 付费 RPC 服务 | 中 | 稳定性要求高时 |
| 自建节点 | 硬件 + 运维 | 大量历史查询、低延迟 |
| **SQL 类链上数据平台**（Dune 等） | 免费额度 + 付费 | **起步最快**：读别人的 query 是最高效的学习方式 |
| 索引服务 / 子图 | 免费额度 + 付费 | 特定协议的结构化数据 |
| 数据市场的现成数据集 | 付费 | 省时间 |

### 我的起步路线

```
1. 用 SQL 类平台跑现成 query，理解数据结构和指标定义
2. 用公共 RPC 拉特定合约/地址的事件，落地为 parquet
3. 需要大规模历史时，再考虑自建节点或付费服务
```

### 链上数据的核心坑（重申）

| 坑 | 严重性 |
|---|---|
| **PIT 问题（地址标签是今天的知识）** | **最严重**，见 [`04-ml-and-frontier/05`](../04-ml-and-frontier/05-alt-data-and-nlp.md) |
| 地址聚类不可靠 | 高 |
| 交易所内部转账污染资金流指标 | 高 |
| 链重组 | 中 |
| 多链碎片化 | 中 |
| 数据量极大 | 中 |

**规避策略：优先用不依赖标注的指标**（活跃地址数、大额转账笔数、合约调用数、协议利用率）。

## 五、存储成本估算（做规划用）

粗略量级（用于判断可行性）：

| 数据 | 单标的单日量级 | 20 标的 2 年 |
|---|---|---|
| 日线 | 极小 | 可忽略 |
| 1 分钟线 | 小 | 几十 MB |
| 逐笔成交 | 中-大 | 几十到几百 GB |
| L2 深度（10 档，秒级） | **大** | **TB 级** |

### 结论

- K 线 + 资金费 + OI：**随便存**，本地硬盘足够
- 逐笔成交：**选择性存**（只存重点标的）
- L2 深度：**必须做取舍**（少数标的 + 采样降频 + 压缩）

**建议**：先只对 3-5 个重点标的采 L2，用于 lab-04 的做市模拟。全量 L2 不现实也不必要。
