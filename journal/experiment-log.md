# 实验日志（试验次数记录）

> ⚠️ **这是最容易偷懒、也最致命的一个文件。**
>
> 没有试验次数记录，就无法计算 Deflated Sharpe Ratio，也就无法知道你的"发现"里有多少是运气。

---

## 为什么必须记

在 α=0.05 下测试 N 个无效策略，**预期会有 0.05×N 个"显著"结果**：

| 测试次数 | 期望假阳性 |
|---|---|
| 20 | 1 |
| 100 | 5 |
| **500**（一次参数网格扫描的常规规模） | **25** |

而你只会保留最好的那个，然后以为找到了 alpha。

**这就是回测过拟合的数学本质。** 唯一的对抗方式是诚实计数 + DSR/PBO 修正。

详见 [`03-research-infra/03-backtest-pitfalls.md`](../03-research-infra/03-backtest-pitfalls.md) 第 3 类。

| 纯性能优化的重跑 | |

## 淘汰记录（防止重复踩坑）

比成功记录更有用：记下"我试过并且失败了"，避免半年后重复。

| 日期 | 想法 | 为什么失败 | 是否值得以后重试 |
|---|---|---|---|
| | | | |

### "为什么失败"的分类

填这一栏时用这些标签，方便后续统计：

| 标签 | 含义 |
|---|---|
| `成本` | 毛收益正但扣成本后负 |
| `容量` | 有效但容量太小 |
| `过拟合` | 样本外失效 |
| `未来函数` | 发现有信息泄漏 |
| `无经济逻辑` | 说不出收益来源 |
| `衰减` | 早期有效近期失效 |
| `拥挤` | 竞争太多 |
| `工程` | 实现难度超预期 |
| `相关性` | 与已有策略高度相关，无增量 |
| `数据` | 数据质量不足以验证 |

**每月统计一次各标签的频次。** 如果 `成本` 出现最多，说明我在选策略时系统性地低估了成本 —— 那就该在设计阶段就先算成本。这种元层面的自我诊断，只有靠记录才能做到。
