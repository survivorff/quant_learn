# 02 · 执行成本与滑点

> **成本模型比 alpha 模型更决定生死。** 这是整个仓库里最该刻在脑子里的一句话。
>
> 一个夏普 2.0 的回测，成本假设从 0 改成真实值之后经常变成负的。所以：先建成本模型，再谈策略。

---

## 一、成本分解

一笔交易的总成本（implementation shortfall）：

```
总成本 = 手续费 + 价差成本 + 市场冲击 + 时机成本 + 机会成本
```

| 成分 | 含义 | 可控性 |
|---|---|---|
| 手续费 | 交易所收取，maker/taker 不同 | 高：做 maker、提 VIP 等级、用抵扣币 |
| 价差成本 | 吃单要付半个价差 | 高：改用限价单 / post-only |
| 市场冲击 | 你的成交推动价格 | 中：拆单、延长执行时间 |
| 时机成本 | 执行期间价格自然漂移 | 低：与冲击成本此消彼长 |
| 机会成本 | 没成交导致的错失 | 中 |

### 核心张力

> **拆单降低冲击成本，但拉长执行时间会增加时机成本。**

这就是最优执行问题（Almgren-Chriss 框架）的本质：在冲击和风险之间找平衡。执行速度不是"越慢越好"。

---

## 二、市场冲击模型

### 平方根律（square-root law）

实证上最稳健的经验规律：

```
冲击 ≈ Y · σ · √(Q / V)
```

- `Q` = 订单量
- `V` = 日均成交量（同周期）
- `σ` = 波动率
- `Y` = 常数，实证上大致在 0.5-1 附近（需自己校准）

**关键含义：冲击是非线性的。** 订单量翻 4 倍，冲击只翻 2 倍 —— 但反过来说，量增大时成本增长不会因为"策略好"而消失。这直接给出了**策略容量上限**。

### 临时冲击 vs 永久冲击

| 类型 | 说明 |
|---|---|
| 临时冲击 | 成交后价格部分回复（流动性补充） |
| 永久冲击 | 价格永久移动（你的交易传递了信息） |

永久冲击的比例决定了"来回交易"的成本。如果冲击全是永久的，那你买进卖出都在自己吃自己的亏。

### 实务：怎么估自己的冲击

不要照搬论文参数，用自己的实盘数据校准：

1. 记录每笔订单的：下单时间、决策价（decision price）、订单量、成交均价、执行时长
2. 计算 slippage = (成交均价 − 决策价) × 方向
3. 对 `slippage / σ` 与 `√(Q/V)` 做回归，得到你自己的 `Y`
4. 按标的、时段、波动率分组分别估计

**这是 TCA（交易成本分析）的核心**，也是从"回测选手"变成"实盘交易者"的分界线。

## 三、回测里的成本建模（分级）

按保守程度递增，选一个符合你频率的：

| 级别 | 模型 | 适用 |
|---|---|---|
| L0（不可用） | 按收盘价成交，零成本 | 只能用来 debug 逻辑，不能看收益 |
| L1 | 固定手续费 + 固定 bps 滑点 | 低频策略的最低要求 |
| L2 | 手续费 + 半个实际价差 + 平方根冲击 | 中频策略的合理基线 |
| L3 | 用真实 L2 深度逐档"吃穿"计算成交均价 | 中高频必须 |
| L4 | 完整订单簿重放 + 队列位置模拟 + 延迟建模 | 做市/高频策略必须 |

### L3 的做法（推荐从这里开始）

用历史深度快照，模拟市价单逐档吃：

```python
def fill_market_order(book_side, qty):
    """按档位吃单，返回成交均价与实际成交量"""
    filled, cost = 0.0, 0.0
    for price, size in book_side:          # 已排序
        take = min(size, qty - filled)
        cost += take * price
        filled += take
        if filled >= qty:
            break
    return (cost / filled if filled else None), filled
```

注意：这仍然**乐观**，因为它假设：
- 深度快照就是你下单那一刻的真实深度（忽略延迟）
- 你的订单不会引起其他人撤单（实际上会，这叫 liquidity fade）
- 没有其他人和你同时抢

### L4 的额外要素（做市必须）

| 要素 | 怎么建模 |
|---|---|
| 延迟 | 行情延迟 + 下单延迟，用实测分布采样，不用固定值 |
| 队列位置 | 记录你挂单时该价位已有的量，只有前面的量被吃完你才成交 |
| 逆向选择 | 你的限价单在价格不利变动时更容易成交（这是做市亏损的主要来源） |
| 撤单竞争 | 你想撤单时可能已经被吃 |
| 部分成交 | 常态，不是例外 |

**如果你的做市回测没有建模队列位置和延迟，结果毫无意义。** 这是做市回测最大的坑。

### 一个必须做的检验

对成本参数做**敏感性分析**：手续费/滑点从 0 逐步加到 2 倍保守估计，画出夏普曲线。

- 曲线陡降 → 策略靠低成本假设活着，实盘会死
- 曲线平缓 → 策略有安全边际

**规则：只接受在 2 倍保守成本下仍然正期望的策略。**

## 四、执行算法

| 算法 | 逻辑 | 适用 |
|---|---|---|
| TWAP | 按时间均匀拆单 | 简单基线，可预测性强（也容易被别人预测） |
| VWAP | 按历史成交量分布拆单 | 想贴近市场均价 |
| POV (participation) | 保持占市场成交量固定比例 | 自适应流动性，crypto 里实用 |
| Implementation Shortfall | 最小化相对决策价的总成本 | 有 alpha 衰减时（信号有时效性） |
| Almgren-Chriss | 冲击与风险的显式权衡最优解 | 理论框架，实务作为参考 |
| Liquidity-seeking | 主动寻找深度，被动挂单为主 | 大单、流动性差的标的 |
| Passive / post-only 挂单 | 只做 maker，等成交 | 低频、无时效性的信号 |

### 个人交易者的实用做法

大多数情况下你不需要复杂算法，需要的是纪律：

1. **信号无时效性（低频）→ 用 post-only 限价单挂在盘口内侧，慢慢成交**。省下来的价差和费率就是纯利润。
2. **信号有时效性 → 用 Limit IOC 加价格保护**，接受付价差，但不接受无限滑点。
3. **单笔超过盘口深度 20% → 必须拆单**。这个阈值要按标的实测。
4. **避开流动性最差的时段**（crypto 里通常是 UTC 凌晨的部分时段，但要自己统计验证）。
5. **给每个标的设"最大单笔金额"**，按其真实深度算出来，硬编码在风控里。

### maker 策略的隐藏成本

用 post-only 挂单看起来免费，但有两个真实成本：
- **不成交风险**：你以为建了仓，实际没有。信号过期了单还挂着。
- **逆向选择**：成交的时候往往是你不想成交的时候（价格要往不利方向走）。

所以 maker 策略必须配一个"超时转 taker"的兜底规则，并统计它的触发频率。

## 五、TCA：交易成本分析

实盘之后必须做的事。每笔订单记录：

| 字段 | 用途 |
|---|---|
| 信号时间 / 决策价 | 计算完整的 implementation shortfall |
| 下单时间 / 下单价 / 类型 | 计算下单延迟 |
| 成交时间 / 成交均价 / 成交量 | 计算滑点 |
| 下单时的 BBO 与深度 | 归因：是价差成本还是冲击成本 |
| 手续费实际值 | 核对费率档位 |
| 是否 maker | 统计 maker 占比 |

### 输出的核心报表

1. **成本归因**：手续费 / 价差 / 冲击 各占多少 bps
2. **实盘 vs 回测成本对比**：偏差有多大，来源是什么
3. **按标的、时段、订单量分组的成本曲线**
4. **maker 成交占比与超时转 taker 的频率**
5. **成本占毛收益的比例**：这是策略健康度的核心指标

> 没有 TCA 的实盘交易，等于闭着眼睛开车。你不知道钱是被市场拿走的还是被自己的执行拿走的。
