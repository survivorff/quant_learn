# 01 · 限价单簿与撮合

> 价格不是"存在"的，是**撮合出来的**。理解了这句话，很多回测幻觉自然消失。

---

## 一、限价单簿（LOB）结构

```
        卖单（asks，价格升序）
        ...
        50,120  ×  3.5   ← ask 3
        50,110  ×  1.2   ← ask 2
        50,100  ×  0.8   ← ask 1 = best ask
  ────────────────────────  spread = 20，mid = 50,090
        50,080  ×  2.1   ← bid 1 = best bid
        50,070  ×  5.0   ← bid 2
        50,060  ×  1.8   ← bid 3
        ...
        买单（bids，价格降序）
```

### 关键量

| 量 | 定义 | 用途 |
|---|---|---|
| Best bid / ask (BBO) | 一档买价/卖价 | 报价基准 |
| Spread | ask1 − bid1 | 基础交易成本；做市商的收入 |
| Mid price | (ask1 + bid1) / 2 | 最常用的"公允价"，但有偏 |
| **Microprice** | `(ask1×Qbid1 + bid1×Qask1) / (Qbid1 + Qask1)` | 用对侧量加权。买盘量大 → 价格偏向 ask。**短期方向预测优于 mid** |
| Depth | 各档累计量 | 决定大单冲击 |
| Book imbalance | `(Qbid − Qask)/(Qbid + Qask)` | 最简单有效的短期方向特征 |
| Order flow imbalance (OFI) | 主动买量 − 主动卖量（按成交方向） | 微观结构里最强的短期预测因子之一 |

微观价格的直觉：如果 bid 上堆了 100 BTC、ask 上只有 0.1 BTC，那"公允价"显然更靠近 ask —— 因为卖方稀缺。中间价会系统性低估这种不对称。

## 二、撮合规则

### 价格-时间优先（price-time priority）

绝大多数 CEX 和交易所用这个规则：

1. 价格优先：买价更高的先成交，卖价更低的先成交
2. 时间优先：同价位先挂的先成交（FIFO 队列）

**推论：队列位置有真实价值。** 同价位排在第一个和第一百个，成交概率天差地别。这是做市策略的核心资产。

### 队列位置的经济含义

- 排在队首 → 高成交概率，但也更容易被**逆向选择**（价格要跌时你的买单先被吃）
- 排队要付"时间成本"：等待期间价格可能不利变动
- 改价（cancel + repost）会**丢失队列位置**，这是做市策略里最重要的取舍：要不要为了跟上价格变动而放弃队首？

工程含义：做市策略的核心不是"报什么价"，而是"什么时候改价、什么时候忍住不改"。这直接对应低延迟需求。

### 其他撮合规则

| 规则 | 说明 | 影响 |
|---|---|---|
| Pro-rata | 同价位按比例分配 | 常见于某些利率期货；挂大单有优势 |
| 集合竞价 (call auction) | 开盘/收盘时段一次性撮合 | crypto 少见，股票市场重要 |
| 自成交防护 (STP) | 防止自己的买卖单互相成交 | 多策略并行时要注意 |
| Post-only | 如果会立即成交就撤单 | **做市策略必用**，保证拿到 maker 费率 |

## 三、订单类型（必须搞清语义差异）

| 类型 | 语义 | 陷阱 |
|---|---|---|
| Market | 立即以最优可得价格成交 | 极端行情下可能吃穿很多档，滑点巨大。**建议永远不用裸市价单** |
| Limit | 指定价格或更好 | 可能不成交；不成交本身是风险（你以为对冲了但没有） |
| Limit IOC | 立即成交剩余撤单 | 用来做"有价格保护的市价单"，**推荐用这个替代市价单** |
| Limit FOK | 全部成交否则撤单 | 套利腿必须全成时用 |
| Post-only | 只做 maker，会立即成交则撤单 | 做市必备 |
| Stop / Stop-limit | 触发价到了才下单 | 触发后仍是普通单，会滑点；交易所端触发有延迟 |
| Trailing stop | 跟踪止损 | 交易所实现各异，谨慎依赖 |
| Reduce-only | 只允许减仓 | **风控利器**，防止对冲单意外开反向仓 |
| Iceberg / Hidden | 隐藏部分数量 | 减少信息泄露，但可能牺牲队列优先级 |
| TWAP / VWAP（交易所原生） | 交易所帮你拆单 | 方便但不透明，大额建议自己拆 |

### 实务规则

1. **不用裸市价单**，用 Limit IOC 加上可接受的最差价格。极端行情下这会救你。
2. **减仓单一律加 reduce-only**。这条能防住一整类灾难性 bug。
3. **对冲腿用 FOK 或者做好单腿风险处理**。单腿成交（legging risk）是套利策略的主要死因。
4. 每个交易所的订单类型语义都有细微差别，**必须读文档并在测试网验证**，不要假设。

## 四、订单流的实证特征

这些是做短周期预测的基础事实：

| 特征 | 内容 |
|---|---|
| 大部分订单会被撤销 | 撤单率常在 90%+。挂单量不等于真实意图 |
| 订单大小分布幂律 | 少数大单主导 |
| 订单到达聚集 | Hawkes 过程可建模自激发特性 |
| 价差与波动率正相关 | 波动大时做市商拉宽价差 |
| 深度与波动率负相关 | 波动大时深度变薄 → 滑点非线性放大 |
| 日内周期性 | crypto 也有，跟随亚/欧/美时段的活跃度 |
| Bid-ask bounce | 成交在买卖价间跳动，造成收益率的**虚假负自相关**。不是 alpha，是噪声 |

### 关键警告：bid-ask bounce

用成交价算高频收益率，会看到显著负自相关，看起来像"完美的均值回归 alpha"。这是价差跳动的假象。实盘上你无法赚到它，因为你每次都要付价差。

**修正方式**：用中间价或微观价格计算收益率，不用成交价。

## 五、Crypto 交易所的特殊性

| 方面 | 说明 |
|---|---|
| 数据免费 | REST + WebSocket 免费提供 L2 深度、逐笔、K 线。传统市场这是天价数据 |
| 深度快照 vs 增量 | WS 通常推增量更新，需要用 snapshot + diff 自己维护本地订单簿，且要处理序列号断裂后的重新同步 |
| 限流 | 权重制限流，高频轮询会被封。必须用 WS 而非 REST 轮询 |
| 撮合延迟不确定 | 高波动时交易所自身会拥堵，撤单可能延迟数秒 —— **这是 crypto 做市最大的隐藏风险** |
| 刷量 | 小交易所成交量可能是假的，深度可能是幌骗（spoofing） |
| 无统一时钟 | 交易所时间戳与本地时间有偏差和抖动，跨所策略要做时钟同步 |
| 宕机与降级 | 极端行情时交易所可能限流、拒单、甚至暂停交易。**必须假设这会发生** |

工程含义（我的强项）：本地订单簿维护 + 断线重连 + 序列号校验 + 状态对账，这是一套典型的分布式一致性工程问题。做对了就是护城河。
