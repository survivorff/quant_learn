# 04 · 链上执行与 MEV

> 链上是另一套微观结构：**没有队列优先，只有区块内排序权的拍卖。**
>
> 我有多链和 Meme 交易经验，这块是差异化优势。但要把"手动交易的直觉"变成"可量化的机制理解"。

---

## 一、链上 vs 链下：根本差异

| 维度 | CEX | 链上 |
|---|---|---|
| 撮合 | 连续、价格-时间优先 | 离散区块、区块内排序可被购买 |
| 延迟 | 微秒-毫秒 | 秒级（出块时间） |
| 信息可见性 | 只看到聚合订单簿 | **待处理交易在公共内存池中可见** |
| 前置风险 | 交易所可能有内部人风险 | 任何人都能看到并抢在你前面 |
| 成本 | 手续费 + 滑点 | gas + 滑点 + MEV 损耗 |
| 执行确定性 | 高（除极端行情） | 低（可能失败仍付 gas、可能被夹） |
| 托管 | 交易所托管 | 自托管 |
| 数据 | 交易所 API | 全量历史可查，**这是链上最大的数据优势** |

**核心差异：链上的"待成交订单"是公开的**。你的意图在被执行之前就被所有人看到了。这从根本上改变了执行策略。

## 二、AMM 定价机制

### 恒定乘积（Uniswap v2 类）

```
x · y = k
```

买入 Δy 数量的 y，需要付出的 x：

```
Δx = (x · Δy) / (y − Δy)
```

滑点随交易规模**非线性**上升。池子越小，滑点越陡。

### 集中流动性（Uniswap v3 类）

LP 只在指定价格区间内提供流动性：
- 区间内资金效率大幅提升
- 价格移出区间后 LP 变成单一资产、停止赚费
- 需要主动管理区间 → 本质上是一个**主动做市策略**

### 无常损失（impermanent loss）

LP 相对于"简单持币"的相对损失。本质是：**LP 卖出上涨的资产、买入下跌的资产**（被动的反向交易）。

```
IL 随价格偏离程度上升；价格回归则 IL 消失（所以叫"无常"）
```

LP 的真实盈亏 = 手续费收入 − 无常损失 − gas。

**判断 LP 是否值得做的关键**：手续费收入能否覆盖无常损失。这需要建模，不能凭感觉。这是一个可量化的"提供流动性收风险溢价"策略，属于风险溢价类。

### 其他曲线

| 类型 | 特点 | 用途 |
|---|---|---|
| StableSwap（Curve 类） | 在锚定价附近近似恒定和，滑点极低 | 稳定币、同价资产对 |
| 加权池（Balancer 类） | 多资产、可自定义权重 | 指数化池 |
| 动态费率 / 集中流动性变体 | 按波动率调整费率 | 减少 LP 逆向选择 |

## 三、MEV：最大可提取价值

### 定义

通过**重排、插入、审查**区块内交易而获得的价值。链上的"排序权"是一种可拍卖的资源。

### 主要形式

| 类型 | 机制 | 受害者 |
|---|---|---|
| **三明治攻击** | 在你的买单前插一笔买、后插一笔卖 | 大额低滑点保护的 swap 用户 |
| **抢跑（frontrun）** | 复制你的有利交易并抢先执行 | 套利者、清算者 |
| **尾随（backrun）** | 在你的交易后执行获利交易 | 通常无害（甚至有益，价格被修正） |
| **DEX-DEX 套利** | 不同池间价差 | 无受害者，属于价格发现 |
| **CEX-DEX 套利** | 链上链下价差 | 无受害者 |
| **清算** | 抢先清算抵押不足的头寸 | 借贷协议的借款人（本来就要被清算） |
| **JIT 流动性** | 在大额 swap 前后瞬时提供/撤回流动性 | 长期 LP（被抢走手续费） |

### 供应链结构

```
用户 → 钱包/RPC → 内存池 或 私有通道 → searcher（构造捆绑包）
     → builder（构造区块） → proposer/validator（提议区块） → 上链
```

关键点：
- **公共内存池 = 你的意图公开** → 会被夹
- **私有通道 / 订单流拍卖（OFA）** → 交易不进公共池，避免被夹，有的还返还部分 MEV 给你
- searcher 之间通过竞价（priority fee / builder 支付）竞争排序权

### 作为交易者的防御手段

| 手段 | 效果 |
|---|---|
| 用支持 MEV 保护的 RPC / 私有内存池 | **最有效**，交易不暴露在公共池 |
| 收紧滑点容忍度 | 让夹子无利可图（代价：交易更容易失败） |
| 拆单 | 减少单笔的可提取价值 |
| 用聚合器并选择低 MEV 暴露路径 | 减少路径上的可夹点 |
| 避开小池子 | 小池滑点大 = 夹子利润大 |
| 用 CEX 做大额、用 DEX 做长尾 | 按流动性选场所 |

### 作为量化研究者的机会

老实说：**纯 MEV searcher 竞争极度激烈**（延迟 + 基础设施 + 资本），和 HFT 一样属于我的"不做清单"。

但有几个衍生方向是可做的：
1. **MEV 数据作为替代数据**：三明治密度、套利量、清算量 → 反映链上真实流动性压力与情绪
2. **CEX-DEX 价差监控**：不一定自己抢，但价差水平是流动性和情绪的高质量信号
3. **避免被 MEV 吃掉**：把执行成本降下来，这本身就是收益
4. **链上活动因子**：巨鲸转账、智能资金地址行为、代币解锁、桥资金流 —— 传统 quant 完全没有的数据源

**第 4 条是我最该发力的**：链上数据是 crypto 独有的、免费的、传统 quant 不熟悉的替代数据源。见 [`04-ml-and-frontier/05-alt-data-and-nlp.md`](../04-ml-and-frontier/05-alt-data-and-nlp.md)。

## 四、链上执行的工程现实

做链上量化必须处理的问题：

| 问题 | 说明 |
|---|---|
| 交易失败仍付 gas | 需要模拟（simulate）后再发送 |
| Nonce 管理 | 并发发送多笔交易时的顺序与替换（RBF） |
| Gas 定价 | 定太低不上链，定太高吃掉利润；需要动态估计 |
| 重组（reorg） | 已"确认"的交易可能回滚，状态要能回退 |
| RPC 可靠性 | 公共 RPC 不稳定、有速率限制、可能返回过期状态。需要多 RPC 冗余 + 自建节点 |
| 状态同步 | 链上状态查询有延迟，套利需要极新的状态 |
| 多链差异 | 出块时间、finality、gas 模型、MEV 生态各不相同 |
| 私钥管理 | **最高优先级安全问题**。热钱包最小化、密钥隔离、限额、绝不入 git |
| 合约风险 | 你交互的合约可能有漏洞或后门 |

### 安全底线（不可妥协）

1. 私钥/助记词**绝不**进代码库、环境变量文件要 gitignore、最好用硬件签名或 KMS
2. 交易机器人用**独立的、限额的**热钱包，主资金在冷钱包
3. 对合约的 approve 额度设上限，不给无限授权，定期检查并撤销
4. 每笔交易先本地模拟，验证预期输出
5. 设每日交易额上限的硬熔断
