# 02 · 量化岗位与面试准备

> 目标定位：**Crypto 量化 / 交易所方向的 QD（量化开发）或交易系统架构师。**
>
> 策略：不跟数学 PhD 拼 alpha 研究，用"强工程 + 懂交易业务 + crypto 内部视角"这个稀缺组合打。

---

## 一、岗位分类与要求

| 岗位 | 主要职责 | 硬要求 | 我的差距 |
|---|---|---|---|
| **QR（研究员）** | Alpha 研究、因子挖掘、模型 | 数学/统计/ML 深度；常见 PhD | 大（需 2-3 年） |
| **QD（量化开发）** | 回测框架、执行系统、数据平台 | 系统设计、性能、可靠性；C++/Rust/Python | **小** |
| **QT（交易员）** | 策略运维、实时风险、参数调整 | 市场理解、风险直觉、抗压 | 中 |
| **交易系统架构师** | 整体架构、低延迟、稳定性 | 架构 + 交易业务 | **小** |
| **数据工程** | 行情/替代数据管道、存储 | 数据工程 | **小** |
| **风控/中台开发** | 风控引擎、限额、对账 | 金融业务 + 工程 | **小** |

### 我的目标顺序

```
1. Crypto 量化机构/做市商的 QD 或交易系统方向    ← 最匹配
2. 交易所的衍生品/撮合/风控系统                  ← 我有直接对口经验
3. Crypto 量化机构的数据工程/研究平台            ← 匹配
4. 传统自营的 QD（需补 C++/低延迟）             ← 需准备
5. QT（需要实盘 track record 支撑）             ← 长期
```

## 二、面试考察维度

### QD 岗位的典型面试轮次

| 轮次 | 考什么 | 准备重点 |
|---|---|---|
| 简历筛选 | 背景匹配度 | 简历要突出交易/金融系统经验 |
| 算法/编程 | 数据结构、算法、编码质量 | LeetCode 中等难度 + 手写无 bug 代码 |
| **系统设计** | 交易系统架构 | **我的强项，要打成亮点** |
| 语言深度 | C++/Java/Python 底层 | Java 是强项；C++ 需补 |
| 概率/统计 | 基础概率题、期望、条件概率 | 需系统准备 |
| 金融/市场知识 | 微观结构、产品、策略常识 | **crypto 是我的加分项** |
| 项目深挖 | 你做过的系统的细节 | 准备 3 个深度案例 |
| 行为面 | 动机、团队、抗压 | 转型动机要讲清楚 |

### 各维度的准备状态与计划

| 维度 | 现状 | 计划 |
|---|---|---|
| 算法编程 | 需要恢复手感 | 系统刷题，重点：数组/哈希/堆/DP/二分 |
| 系统设计 | **强** | 准备"设计一个交易系统"的完整答案 |
| Java 深度 | **强** | 直接可用（JVM、并发、GC） |
| C++ | 弱 | 至少能读懂 + 聊清 RAII/智能指针/移动语义 |
| Rust | 无 | 做一个订单簿项目（见 `06-engineering/04`） |
| 概率统计 | 中 | 刷经典面试题（Joshi / Crack 的书） |
| 微观结构 | **中-强**（有 CEX 经验） | 系统化，能讲清撮合/强平/资金费 |
| 策略常识 | 补齐中 | `02-strategy-zoo` 通读后即可 |
| 项目案例 | **强** | 整理成 STAR 结构 |

## 三、我的核心叙事（面试的主线）

面试的成败很大程度取决于**你的故事是否自洽**。

### 一句话定位

> "10 年后端工程师，做过 CEX 的交易相关系统，同时是 crypto 一线交易者。我在业余搭了一套完整的量化研究与实盘系统，现在想把工程能力和交易理解结合起来，做量化交易系统。"

### 为什么这个叙事有效

| 要素 | 作用 |
|---|---|
| "10 年后端" | 硬实力背书 |
| "做过 CEX 交易系统" | 领域相关性，不是跨界小白 |
| "crypto 一线交易者" | 有市场理解，不只是写代码 |
| **"业余搭了完整系统"** | **证明真的在做，不是空想** |
| "想把两者结合" | 动机自洽，不是"工作不好找所以转行" |

### 必须准备好的追问

| 追问 | 我的答案要点 |
|---|---|
| "为什么现在转量化？" | 不说"工作不好找"。说：交易所工作让我看到了交易系统的核心，我想深入这个方向 |
| "你的策略赚钱吗？" | **诚实**：小额实盘，重点在验证系统和方法论，不是收益。**吹收益会被问穿** |
| "你懂交易还是只懂编程？" | 用具体细节证明：讲清资金费机制、强平级联、成本模型、TCA |
| "为什么不做 QR？" | 诚实：数学背景不够深，但我在工程和执行侧有明显优势，这是我的比较优势 |
| "你的系统有什么特别的？" | 讲工程质量：PIT 正确性、幂等、对账、故障注入、CPCV 验证 |
| "你怎么防止过拟合？" | 讲 DSR、试验次数记录、CPCV、PBO —— **这个答案能立刻区分内行和外行** |

### 最后一个问题最重要

**"你怎么防止过拟合"是量化面试的试金石。**

外行的答案："用样本外测试"
内行的答案："记录累计试验次数并用 Deflated Sharpe 修正、用 CPCV 得到夏普分布而不是点估计、算 PBO、保留只看一次的 holdout、多周期平均代替选最优参数、成本敏感性分析、必须能说出经济逻辑"

**能给出后者，你的可信度会立刻不同。** 这也是 [`03-research-infra`](../03-research-infra/) 的价值所在。

## 四、作品：labs 就是简历

比简历上的文字更有说服力的是可运行的代码。

### 优先打磨的三个作品

| 作品 | 展示什么 | 对应 lab |
|---|---|---|
| **1. 事件驱动回测框架** | 系统设计、防未来函数、成本建模、crypto 特有机制（资金费/强平） | `lab-02` |
| **2. 因子研究流水线** | 研究工程化、CPCV/DSR 验证、自动报告 | `lab-03` |
| **3. 实盘交易系统** | 幂等、对账、风控、监控、故障处理 | `lab-05` |

### 每个作品的 README 必须包含

```markdown
## 解决什么问题
（为什么需要这个东西）

## 设计决策与取舍
（为什么这样设计，考虑过什么替代方案）
← 这一节最能体现水平

## 关键实现细节
（最难的部分是什么，怎么解决的）

## 怎么验证正确性
（测试策略、自测清单）
← 这一节能立刻区分工程水平

## 局限与下一步
（诚实说明做到哪、没做什么）
```

**"设计决策与取舍"和"怎么验证正确性"这两节最重要。** 它们展示的是思维方式，而不只是"我会写代码"。

### 一个额外的加分项

写一篇技术博客：**"我在 crypto 量化回测里发现的 N 个坑"**。

理由：
- 展示深度（这些坑只有真做过才知道）
- 可传播（面试官可能提前看过）
- 是持续输出的开始（对长期职业有复利）

内容素材已经在 [`03-research-infra/03-backtest-pitfalls.md`](../03-research-infra/03-backtest-pitfalls.md) 里了。

## 五、系统设计题：准备一个标准答案

高频题："设计一个加密货币量化交易系统"

### 我的答案框架

```
1. 澄清需求
   - 什么频率？什么策略类型？单所还是多所？资金规模？
   - （主动澄清是高分行为）

2. 整体架构
   - 数据层 / 策略层 / 执行层 / 状态层 / 观测层
   - 画图（见 06-engineering/01）

3. 关键设计决策
   - 事件驱动 vs 向量化，为什么选事件驱动
   - 目标仓位模式 vs 事件式接口
   - 风控引擎为什么必须独立
   - 单线程 vs 多线程

4. 难点与解法
   - 本地订单簿一致性（序列号 + 定期全量校验）
   - 幂等下单（client_order_id + 超时先查询 + UNKNOWN 状态）
   - 对账（三源对比 + 不一致停机）
   - 资金费与强平的建模
   - 精度（整数最小单位）

5. 可靠性
   - 故障场景与降级策略
   - 监控指标与告警
   - 故障注入测试

6. 扩展性
   - 多交易所（adapter + venues 配置）
   - 多策略（进程隔离 + 仓位聚合）
   - 性能瓶颈时的演进路径（numba → Rust 热路径）
```

**这个答案的每一部分我都能讲出细节，因为我真的做过。** 这是和"背过系统设计模板"的人的根本区别。

## 六、准备时间表

假设第 9 个月启动求职：

| 时间 | 内容 |
|---|---|
| 月 7-8（提前） | 整理 3 个作品的 README；写技术博客 |
| 月 9 第 1-2 周 | 简历重写；调研目标公司与 JD 关键词 |
| 月 9 第 3-4 周 | 算法刷题恢复手感；概率统计面试题 |
| 月 10 | 系统设计答案打磨；C++ 基础补齐；开始投递 |
| 月 10-11 | 面试 + 复盘迭代 |
| 月 11-12 | 谈 offer / 或继续打磨 |

### 一条重要建议

**不要等"准备好了"才开始投递。** 前几次面试就是最好的信息收集：

- 摸清市场真实要求
- 发现自己的盲点
- 校准薪资预期
- 了解各家的个人交易政策

**建议：先投 3-5 家"不太想去的"公司做练习**，收集信息，再投目标公司。
